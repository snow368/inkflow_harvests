# InkFlow Marketing 内容 SEO 规则集

## 原则

**每个页面只有一个主推关键词。** URL、标题、H1、内链锚文本全部围绕这个词展开。

---

## 1. 主推关键词

- 每页选 **1 个主推词**，2-4 个相关长尾变体
- 主推词需满足：有搜索量 + 匹配页面意图 + 你能排进前 10
- 主推词决定该页的 **URL slug**

## 2. URL Slug

- 用主推词的完整短语，连字符分隔，全小写
- ≤ 5 个词 / ≤ 60 字符
- 去掉 a, an, the, of, for, in, to, with（停用词）
- 类和功能页 > 内容页 > 工具页，slug 优先级依次递减
- **已有页面的 slug 绝不更改**（已收录，改即丢权重）；新页面一次做对
- slug 里可以不包含大类词（如 "tattoo"），只要 title/H1 补上即可

## 3. Meta Title

- 必须包含主推词，**靠近开头**
- ≤ 60 字符（Google 截断线）
- 格式：`主推词 - 品牌名` 或 `主推词 | 品牌名`
- 每页 title 唯一，不重复
- **Title 与 H1 必须包含完全相同的主推词短语（字面一致，非仅语义一致）**，见第 5 节 H1 规则

## 4. Meta Description

- 自然包含 1 次主推词，不堆砌
- ≤ 160 字符
- 写"用户读完能获得什么"，不是写产品介绍
- 末尾可加行动召唤（CTA），但不强求

## 5. 标题层级与 H2-H6 界定

| 层级 | 主推词要求 | 说明 |
|------|-----------|------|
| **H1** | ✅ **必须包含** | 每页仅 1 个，且**必须与 Meta Title 使用完全相同的主推词短语**（字面一致，不只语义一致） |
| **H2** | ⚠️ 子话题 / 长尾变体 | 覆盖主推词的子意图拆分；**最多 1 个 H2 自然带精确主推词**（定义式 / 对比式），其余用长尾变体 + 相关实体 + 角度词展开，禁止每个 H2 重复精确主词 |
| **H3-H6** | ❌ 不需要 | 仅作 H2 下的自然语言细分（列表 / 对比维度 / FAQ 子问 / 步骤）；不硬塞主词，自然出现即可 |

### H2-H6 界定铁律
- **精确主推词的主场 = Title + H1 + 第一段前两句**。H2-H6 重复精确主词 = 页内自蚕食 + 堆砌嫌疑，禁止。
- **H2 的职责 = 把主推词「拆开讲」**：每个 H2 是一个独立子话题 / 意图（功能点 / 场景 / 对比 / 痛点 / 流程 / FAQ）。
  - 长尾变体（每页 2-4 个）在 H2 + 正文出现 3-6 次，承担「覆盖同义词 / 问法」，把精确主词从 H2 释放出来。
  - 例（tattoo-crm-software）：H2 = `What Is Tattoo-Specific CRM?`(定义,带变体) / `InkFlow CRM vs Generic CRMs`(对比) / `Client History That Drives Rebooking`(功能) / `Automated Campaigns`(功能) / `Client Portal`(功能) / `FAQ`(疑问)。
- **H3-H6 无关键词配额**：只当 H2 下的细分结构用（对比表维度、FAQ 子问、步骤列表）。密度红线：全文主推词密度 < 3%（见第 7 节），H2-H6 不贡献精确主词重复。

## 6. 内链

### 本页面向外链（出链）
- 出链锚文本优先用主推词相关的变体，而非"click here"/"了解更多"
- 每个出链应指向同一主题集群内的其他页面
- 一个页面出链数量：3-8 个合理，超过 15 个稀释权重

### 外面链进来（入链）
- 其他页面链向本页时，锚文本尽量用本页的主推词
- 入链来源应在同一主题集群内（相关页面之间互链）

### 主题集群结构

```
Pillar 页（主推词的最宽泛版本）
  ├─ Spoke 1（变体/场景 A）
  ├─ Spoke 2（变体/场景 B）
  ├─ Blog 1（相关问题）
  ├─ Blog 2（对比/指南）
  └─ Free Tool（工具页，低门槛引流）
```

集群内所有页面互相链，锚文本使用相关变体。

## 7. 页面内容

- **第一段（hero 副文案）前两句必须自然带出完整主推词短语**（字面一致，不堆砌）；前 100 字内至少出现 1 次主推词
- 正文中主推词出现 2-4 次（每 300 字约 1 次）
- 相关长尾变体出现 3-6 次
- 禁止关键词堆砌（主推词密度 < 3%）
- FAQ 部分自然覆盖主推词的疑问式变体

## 8. 执行时参照

1. 确定主推词 → 定 slug
2. 写 title → 含主推词、靠近开头、≤60 字符
3. 写 H1 → **必须与 title 含完全相同主推词短语**（字面一致）
4. 写第一段（hero 副文案）→ **前两句带出完整主推词短语**
5. 规划 H2（子话题/长尾变体）
6. 写正文 → 前 100 字出现，全文 2-4 次
7. 加内链 → 出链锚文本用主推词变体，3-8 条
8. 加 FAQ → 覆盖疑问式变体

## 9. 委托式 SEO 维护清单（可批量执行）

> 来源：Mehrab @mehrab_build（X/Twitter，2026-07）。适用于「已有页面周期性提权」与「新页面建页标准」双重场景。AI 可在一下午内批量代执行。

每次维护 / 建页都自检这 5 项：
1. **从 GSC 拉 Top 10 页面** → 作为维护优先级队列（无 GSC 时退化为按流量/价值排序）。
2. **每页加 3 条情境化内链** → 锚文本用主推词变体，指向同集群相关页（见第 6 节）。
3. **Meta Title 对齐精确目标词** → Title 与 H1 字面一致、且 = 该页主推词（见第 3/5 节）。
4. **底部加 FAQ 块** → 覆盖疑问式变体，并注入 FAQPage Schema。
5. **更新发布日期 + 刷新过时数据/案例** → lastUpdated 改为当日；替换过时统计/竞品定价（标 `[suggest verify]` 的待核数据必须刷新或删）。
